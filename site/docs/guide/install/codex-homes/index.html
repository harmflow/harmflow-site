Codex homes as installations

Codex keeps its sign-in, its configuration, and what it knows of its models in a folder of its own, its home. A Mac can hold more than one, for example a personal home and a work home, each signed in to its own account. HarmFlow treats each Codex home it finds as an installation of its own: Settings shows each one apart, a task can name the one it runs on, and each one's home goes only to the processes that run it.

Which homes HarmFlow finds

HarmFlow looks for Codex homes in two places: the .codex folder in your home folder, and the folder that the CODEX_HOME environment variable names in the daemon's environment, when it names another one. The installation in use is the home CODEX_HOME names, or ~/.codex when it names none.

An installation is named by its home's path, written from ~ when the home is in your home folder, such as ~/.codex. A task names an installation the same way, so a task file reads the same on another Mac with the same folders.

What Settings shows

In Settings, the AI tools section has a card for Codex (see What AI tools shows). Its Homes row lists every Codex home HarmFlow found, each by the name a task uses for it, with whether it is ready, and marks the one in use In use. Beside each home, the row shows what that home's own checks read:

  • Its sign-in: whether it is signed in.
  • Its plan, when Codex reports one, and whether an administrator manages its requirements (see Codex's managed requirements).
  • Its models and efforts: the ones that home's Codex offers.
  • Its skills: your skills, as Codex lists them for that home. HarmFlow's built-in skills are not among them.
  • Its quota: the share of each quota window used, from the last reading HarmFlow kept for that installation, taken by the check before an attempt on it or reported by an attempt while it runs. A home no attempt has used yet shows none.

Settings has no field to add a home by hand: the Homes row shows the homes HarmFlow finds, and Detect again looks for them once more. The Installations row above it is another thing: it lists the Codex programs found on your Mac, whichever home they run with.

Choosing a home for a task

In the task editor, a profile whose AI tool is Codex has an Installation choice beside its model and effort, and so does each Codex candidate in the task's Fallback chain. It lists:

  • In use, with the name of the installation in use, first. A profile left on it names no installation, and runs on the installation in use when the task runs.
  • Each home HarmFlow found, with whether it is ready.

So a task can prefer one home and fail over to another, for example from a personal home to a work home when the first one's quota runs out (see Failover when a quota runs out). In the task file, the choice is the profile's installation key.

A task that names an installation this Mac does not list fails validation, and the error names the missing installation:

Codex has no installation "~/.codex-work" on this machine

HarmFlow neither saves nor imports such a task, and a task file that names it, because the home was removed since the task was saved, loads as invalid. The editor shows that installation as not on this machine, so you can choose another. When a home is gone by the time a task fires, the check before each attempt finds it missing and names it the same way: the execution fails over to the next candidate of its fallback chain when it has one, and otherwise fails.

Models and efforts

A model or an effort is checked against the installation the profile names, or the one in use when it names none: a model one home offers and another does not is refused on the profile that names the other. The editor's Model and Effort lists follow the installation chosen, so they offer what that home offers.

Which processes receive a home

Each check of an installation and each attempt on it runs Codex with that installation's home as its CODEX_HOME, in place of any the daemon's environment holds. No other process HarmFlow starts receives it: not Claude Code, not a script task's program, and not the Git, GitHub CLI, and system commands HarmFlow runs.
