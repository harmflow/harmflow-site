A task is a file

Every task is one file in the tasks folder of HarmFlow's data folder. The app's form and a text editor both work on that same file: what you save from the form is written to it, and what you change in it with a text editor shows in the app. This page says what each side sees of the other.

Saving from the form

  • The save writes the file. When you save a task from the form, HarmFlow writes the task's file in the tasks folder, named after the task's identifier, such as weekly-report.yaml. The file holds the values you set in the form and nothing else.
  • The task is listed. The Tasks list shows the saved task by its name, with its identifier beside it.

For where the data folder is and the keys a task file takes, see The task file in the reference.

Editing the file outside the app

You can open a task's file in any text editor and change it. HarmFlow notices the change on its own, within seconds, with no reload and no restart:

  • In the Tasks list. The list shows the task as the file now has it: a name you changed in the file is the name the list shows.
  • In the editor. The task editor, opened next, shows the file's own values in the form, such as its name and its prompt.
  • In the YAML tab. The editor's YAML tab shows the file's text exactly as you wrote it, your comments included.

For example, if you open weekly-report.yaml in a text editor, change the task's name to Weekly report, by hand, and add a comment line such as # Renamed by hand., the list reads Weekly report, by hand, and the YAML tab shows the comment on its line.

Saving from the form after an outside edit

When you open the task in the editor after its file changed, and change it in the form and save, the save is made on the file as it is now, its current revision, not on the task as it was before the outside edit. Afterwards, the file holds what you changed in the form: your form edit is not lost, and it does not bring back what the file held before the outside edit.
