Task templates

When you create a task, you start from a template: a ready-made starting point for one kind of automation. HarmFlow comes with three built-in templates, and you can save any task of yours as a template of your own. This page says how to find a template, what each built-in one sets up, what happens between choosing a template and saving the task, and how your own templates are made and kept.

Where you choose a template

HarmFlow offers the same templates, in the same order, wherever it offers to create a task:

  • the New task button at the top of the window, or its shortcut, ⌘N;
  • the Tasks screen;
  • the Overview, while you have no task yet;
  • the first-run setup.

The catalog lists HarmFlow's templates first and yours after them. Each template's card shows:

  • its name and a description of what it is for;
  • its type: General, GitHub, or Script;
  • its source: Built-in for HarmFlow's templates, Yours for the ones you saved, which also carry a Yours tag.

A built-in template's name and description are in the interface's language. Change the language and they change with it, with no restart. Your own templates show their name and description as you wrote them, in every language.

Finding a template

Above the cards, a search box and two filters narrow the catalog:

  • The search looks in each template's name and description and keeps the templates that hold every word you type, whatever their case and accents.
  • Source keeps the built-in templates or yours; Any source keeps both.
  • Type keeps the templates of one task type; Any type keeps them all.

The search and the filters combine. When no template is left, the catalog says that no template matches the search and filters.

What a template needs

A template can cite an agent or a skill, and run on an AI tool. When this Mac lacks something a template needs, its card says so:

  • Agent not found or Skill not found, with its name, for each agent or skill the template cites that the AI tool it runs on cannot load on this Mac;
  • the AI tool's name and is not ready, when that tool is not ready, such as one that lacks a sign-in.

A script template runs no AI tool, so its card names none of these. A card that names something can still be chosen: the task you create from it is checked when you save it, as any task is.

The three built-in templates

  • General task. Any automation whose behavior lives in its prompt, agents, and skills: an AI tool works on a prompt you write. Its harness is set to Claude Code.
  • Implement GitHub issues. Selects issues, implements them in a worktree, runs the tests, and opens a draft pull request. The task starts as a copy of HarmFlow's built-in issue implementer: its prompt is that agent's, with the skills that pick the issues, prepare the worktree, and open the draft pull request. Its harness is set to Claude Code, and the repository it works starts on the main branch.
  • Script task. Runs a program or a script of yours on a schedule, in place of a launchd agent, the Task Scheduler, or cron. It runs no AI tool.

Choosing a template opens a draft

Choosing a template opens the task editor with a new task already filled in from it. The task is named after the template, such as General task, and gets an identifier no other task has: a second task from the same template becomes general-task-2. You can rename it before you save. The name is set when the editor opens: a later change of language does not rename the task.

The draft is not a task yet. Nothing is saved, enabled, or run until you choose Save. Close the editor before you save, and nothing is written.

What you still fill in

A built-in template leaves open the values only you can give. The editor leaves those fields empty for you; saving without one is refused, and the editor lists each value still missing.

  • General task: the Prompt, what the task does.
  • Implement GitHub issues: the repository it works, in its Repository (owner/repo) and Local path fields. Its prompt and skills are already there.
  • Script task: what it runs: A program with its arguments, or An inline script with its interpreter. Its working directory, variables, and timeout are optional.

None of the three sets a schedule. A task saved without one is Manual only: it runs when you start it. Give it a cron expression or an interval in the editor to have it run on its own.

Built-in templates do not change

The built-in templates ship with HarmFlow. You cannot change or delete them: what you change in the editor belongs to the new task, and the template stays as it was for the next task you create from it.

Saving a task as a template

A task you want to repeat can become a template of your own. On the task's row in Tasks, choose Save as template, then give the template:

  • a Template name, which starts as the task's name;
  • What it is for, the description its card shows;
  • a Template ID, which the dialog proposes from the name until you write one: lowercase letters, digits, and hyphens, never starting with hf-, which only HarmFlow's templates use. An ID another template of yours already has is refused.

The template keeps the task's type and its fields, its prompt included, as you customized it: a task that started from an agent gives a template that holds the prompt as the task has it, not the agent it came from. The template leaves out the task's name, its identifier, whether it is enabled, and where its prompt came from. The task itself stays as it was.

The template joins the catalog after HarmFlow's templates, and creates tasks as a built-in one does. A task whose file has an error cannot be saved as a template until the error is fixed.

A template of yours is a file

Each template you save is one file in the templates folder of HarmFlow's data folder, beside its tasks folder, named after the template's ID, such as weekly-report.yaml. For where the data folder is, see The task file in the reference.

You can change a template's file in any text editor. HarmFlow notices the change on its own, and the catalog shows it. Remove the file in the Finder, and the template leaves the catalog. A file that is no longer valid is no longer offered for a new task, and your other templates stay in the catalog.

A task is its own copy

A task created from a template holds its own copy of the template's values, and keeps no link to the template. Changing or deleting the template changes no task created from it, and a new release of HarmFlow that changes a built-in template changes none either.
