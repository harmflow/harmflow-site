Creating tasks

A task is one automation HarmFlow runs for you, kept as one file in HarmFlow's data folder. It holds:

  • Its type. A general task, a GitHub task that works GitHub repositories, or a script task.
  • Its work. The prompt, agents, and skills its harness works with, or, for a script task, the program it runs.
  • Its schedule. A cron expression or an interval, and what to do about a run your Mac slept through.
  • Its harness. The one it prefers, Claude Code or Codex, and the ones it falls back to.
  • Its permissions. A profile HarmFlow translates into the harness's own controls.
  • A script task's systems and run record: which systems a script task runs on, what the app shows when it does not run, and what the record of a run keeps and hides.
  • A script task's working directory, variables, and timeout: where a script task's program starts, which variables it sees, and when it is stopped.
  • What a script task does not take: the settings of other tasks a script task leaves out, and what HarmFlow says when a task file sets one.
  • Exporting and importing a task: what an exported task's file holds and leaves out, and what you see after an import.
  • Editing a task as YAML: how the editor's YAML tab relates to the form, and what a refused change looks like.
  • A task is a file: what saving from the form writes, and what the app shows when the task's file is edited outside it.
  • Editing a task while it runs: what a running execution keeps, when the edit takes effect, and what an invalid edit changes.
  • Creating a task from a template: what each built-in template sets up, what you still fill in, and why nothing is saved until you save.
  • Which fallback harnesses are valid: the agents and skills a fallback harness must have, the warning the editor shows, and what a run does without them.
  • The record of a task's firings: what HarmFlow records of each firing, what survives a restart, and what a task whose file has an error as the app starts does.
  • When a restriction is not enforced: what the warning means, where it shows, what lifts a restriction, and how to hide it on an execution.
