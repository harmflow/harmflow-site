Live details and replay of an execution

Selecting an execution opens its details: what it is, and the history of its events. While the execution runs, the details follow it as it happens. Once it has ended, you can open it again and read the same history.

Opening an execution

On the Executions screen, select the card of a running execution, or an execution in the Recent history panel beside the cards. Opening an execution from another screen, such as the Overview, brings you to the Executions screen with that execution selected. When you have selected none, the screen shows the first running execution, or else the latest one that ended.

The details open below the cards, with the task's name, the execution's status, and its elapsed time. Their Events view holds the history of the execution's events as a timeline, with the details of the event you choose beside it. The history is complete from the start: the events the execution emitted before you selected it are listed along with the ones that come after.

While it runs

New events of a running execution arrive in the details as they happen, with no refresh needed. Each one is added to the timeline in its place, and the count on the Events view grows with it. When you have chosen no event, the details beside the timeline follow the latest step.

An event is never listed twice, even when it reaches the dashboard by two routes. If the connection to HarmFlow drops, the dashboard reads again what it may have missed as soon as it reconnects.

After it ended

Opening an execution that has ended reads its events again from its log. You see the same events, in the same order, each once, and so the same timeline you could follow while it ran.

Related pages

To move through the timeline without the mouse, and for how assistive technology reads it, see The events timeline and the keyboard. An execution's log is kept only for the retention period; what its details show once the log is gone is in An execution whose log has expired.
