The connection to the daemon

The daemon is the background process that runs your tasks; the dashboard is the window that shows them. The dashboard receives the daemon's events over a connection that stays open, and its top bar always shows the state of that connection. When the connection drops, your executions do not: they go on in the daemon, and the dashboard catches up with them once it is connected again.

The states the top bar shows

In the top bar, a status pill names the connection's state. Beside it, Last update gives the time of the last update the dashboard received from the daemon. The pill reads one of these:

  • Connecting to the daemon: the dashboard has just opened and is connecting for the first time.
  • Daemon connected: the connection is open, and events arrive as they happen.
  • Reconnecting to the daemon: the connection dropped, and the dashboard is opening it again.
  • Connection to the daemon lost: the connection ended, and the dashboard tries again in a few seconds.
  • Not answering: the daemon is running, but has not answered the dashboard's check in time.
  • Daemon not running: the daemon itself is stopped.

The connection-lost banner

While the pill reads Reconnecting to the daemon or Connection to the daemon lost, a banner below the top bar says: "The connection to the daemon was lost. Executions keep running in the daemon; the dashboard reconnects and replays the events it missed." You have nothing to do: the dashboard keeps trying on its own, and the banner goes once the connection is back.

While the pill reads Not answering, a banner says instead that the daemon is running but not answering yet, and that the dashboard keeps trying.

A lost connection is not a failed execution

A dropped connection is between the dashboard and the daemon only. The daemon keeps running every execution it started, and they go on writing their events to their logs while the dashboard cannot receive them. The dashboard never reads the loss as an execution's end: while the connection is lost, a running execution still reads as running, as it did when the last event arrived, and none reads Failed, Interrupted, or Cancelled because of it. Its card stays in the list of active executions.

A stopped daemon is a different case: the pill reads Daemon not running, and no task runs until the daemon starts again. How to start it is in Starting the daemon by hand.

Once the connection returns

When the connection opens again, the pill reads Daemon connected and the banner goes. The dashboard then asks the daemon for the events after the last one it received, and reads again the lists of active and recent executions and the details of each execution it has open. So each execution shows as it now stands: one still running with the events it emitted while the connection was lost, and one that ended meanwhile with the status it ended with. The details of an open execution receive those events in their place in its timeline, as Live details and replay of an execution describes.
