Reading executions

Each time a task fires — on its schedule, on wake for a run your Mac slept through, or by hand — HarmFlow starts an execution of it. The execution starts the task's harness in a workspace of its own and records the progress and the report the session leaves.

The dashboard receives every event of an execution as it happens, so you can follow it while it runs and read it again once it ended. When the harness's quota runs out, or the harness is unavailable, the execution moves to the next harness the task names, and HarmFlow then notifies you.

  • The events timeline and the keyboard: stepping through an execution's events without the mouse, and how assistive technology reads them.
  • An execution whose log has expired: what a task's history still shows once an execution's log is gone, and the notice it shows.
  • The list of active executions: what each card of a running execution shows on the Executions screen, and how to cancel one.
  • An execution whose report was ignored: why it reads Needs attention, and how its reason and its warning name the field at fault.
  • One timeout across a failover: why a switch to a fallback harness starts no new timeout, and how late the execution can end.
  • Notices held while no dashboard is open: that HarmFlow keeps them, where they appear when the dashboard opens, and that opening it does not mark them read.
  • The notification level: one level in Settings for every task, its three choices, and how it filters the events each task chooses.
  • A script task's output: what the dashboard shows while the program runs, what the log keeps afterwards, and how secrets in it are redacted.
  • The share of each harness's quota: how much of each quota window HarmFlow may spend, where to set it, and what it never interrupts.
  • The queue panel's statuses: what To resume and To retry mean, which work items appear under each, and when an item needs attention.
