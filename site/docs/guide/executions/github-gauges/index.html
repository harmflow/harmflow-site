Follow on GitHub

The sidebar's GitHub gauges

A task that works GitHub issues makes requests to GitHub with the login signed in to the GitHub CLI, gh, on your Mac, and GitHub limits how many requests that login may make in an hour. The sidebar's GitHub gauges show how close the login is to those limits, so you can see it before a task runs into them.

Where the gauges are

With the sidebar expanded, its foot holds two widgets. The GitHub widget sits directly above the System widget, and has two gauges:

  • REST: the limit of GitHub's REST API.
  • GraphQL: the limit of GitHub's GraphQL API.

With the sidebar collapsed to its icons with ⌘B, neither widget shows.

What each gauge shows

Each gauge shows what the login used in the current hour against the limit GitHub reports for it, in two ways:

  • As text, the requests used and the limit, such as 1,234 / 5,000.
  • As a bar, filled to the share of the limit used. The bar never fills past full, even when GitHub reports more used than the limit.

Below them, Resets at gives the time the hour's count starts again, in hours and minutes, written as times are written in the language the app shows.

Whose count it is

The figure is GitHub's own count for the login, not HarmFlow's. Every request made with that login counts, in HarmFlow or outside it: another tool or a script of yours that uses the same login spends the same limit, and the gauges show it. HarmFlow keeps no count of its own. To read the figure, it asks GitHub for the login's rate limits, a request GitHub counts against no limit, so reading the gauges does not use up what they show.

When the gauges are read

The gauges are read as soon as the sidebar expands, and then every 5 seconds while it stays expanded. While the sidebar is collapsed, nothing shows them and they are not read. The GitHub gauges are read apart from the System gauges, so a slow answer from GitHub never holds the System gauges back.

When the gauges read a dash

Both GitHub gauges read "—", with an empty bar and no reset time, when HarmFlow cannot read the count:

  • gh is not installed, or HarmFlow does not find it.
  • gh is not signed in.
  • The request fails, or its answer cannot be read.
  • The daemon, the background process that runs your tasks, is an older version that does not offer the reading.

A reading that fails shows the dash rather than the last figure, since the count changes with every request the login makes. The System gauges keep working all the while. Once gh is installed and signed in, the next reading shows the figures again. How a task reaches GitHub through gh is in Granting access to repositories.
